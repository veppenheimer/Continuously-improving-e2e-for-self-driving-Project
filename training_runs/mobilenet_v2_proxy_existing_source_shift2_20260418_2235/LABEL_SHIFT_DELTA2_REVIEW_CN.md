- 数据源: `E:\桌面\data`
- 代理正式数据集: `E:\桌面\项目\dataset\formal_view_proxy_existing_source_shift2_20260418_2235`
- 标签前移: `Δ = 2`
- 监督定义: `image_t -> steering_(t+2)`
- 模型: `MobileNet v2` 回归主线
- 输入契约: `Full Image -> HSV -> Resize(144,192) -> Tensor`

说明:

## 关键观察

1. 训练集误差显著下降，但验证/测试几乎始终维持在 `1.08` 左右，说明模型在训练集上能拟合一部分模式，但对验证集基本无法泛化。
2. 这更像是任务定义与当前画面可观测信息不匹配，而不是单纯训练失败。
3. 相比不做标签前移的版本，本轮性能显著恶化，说明在当前视角和单帧设置下，`Δ=2` 对模型来说过于超前。

## 与原始序列跳变对比

基于源数据顺序统计:

- 原始相邻帧:
  - 平均角度变化: `0.2768`
  - 跳变 >= 1.0 的对数: `255`
  - 从接近 0 直接跳到大角度的对数: `100`

- 前移 `Δ=2` 后:
  - 平均角度变化: `0.3270`
  - 跳变 >= 1.0 的对数: `304`
  - 从接近 0 直接跳到大角度的对数: `121`

这说明 `Δ=2` 实际上进一步放大了“当前图像与目标转角之间的不连续性”。

## 当前判断

在当前摄像头视角、当前单帧输入设定下，`Δ=2` 并不是一个合适的标签前移量。

更具体地说:

- 它并没有帮模型获得更早的可预测信号
- 反而把目标推到了“图像里还没充分出现，但标签已经要求更大转角”的区间
- 最终造成训练集可拟合、验证集不可泛化的结果

## 结论

本轮 `Δ=2` 标签前移实验，结果应判定为: `不推荐沿用`。

更合理的后续方向是:

1. 回退到更小的标签前移量，例如 `Δ=1`
2. 或者在保持 `Δ=2` 目标不变的前提下，先改变输入信息量，例如更低俯角、更多中距离赛道、或多帧输入
